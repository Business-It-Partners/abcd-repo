## Scope

Recall and follow-up worklist, patient selection, creation and scheduling, rescheduling, permitted status transitions, refresh, and recoverable validation/conflict states.

M18 exercises the app through the Dental OS connected to the SaaS staging backend. Use synthetic staging data only. Production is out of scope. No backend code or direct backend data changes are allowed as an app fix. Route calls listed here are expected through the signed app's SDK and host broker; they are not authorization to call those endpoints directly.

- Parent-plan execution controls, issue taxonomy and backend handoff rules apply.

## API reachability and expected calls

Read through the app SDK: GET /v1/follow-ups; GET /v1/clinic/staff-references; bounded GET /v1/patients for patient selection. Writes: POST /v1/follow-ups; PATCH /v1/follow-ups/:id/schedule; PATCH /v1/follow-ups/:id/toggle. Verify each observed request is brokered under the signed Follow-ups package and current clinic session.

Record each observed call, response status/shape and request ID in the shared [test template](TEST_CASE_TEMPLATE.md). Include missing, unexpected, duplicated or direct-network calls as findings. Startup reads must not be confused with completed business workflow acceptance.

## End-to-end workflows and important states

Load due/today/upcoming/missed worklists; search and select a synthetic patient; create and schedule a follow-up; reschedule it; toggle a permitted completion/status state; refresh and confirm the server result; exercise empty, loading, validation, denied-role/session and stale/unknown-write recovery states.

## Issue classification

Use the shared categories in the [main M18 plan](PLAN.md#issue-classification). App-specific ownership hints:

- **OS/platform fixture:** an otherwise correct package/session is blocked by the shared host, signed Store lifecycle, SDK broker, route allowlist, capability gate, window or media broker.
- **App implementation:** this app issues the wrong query/body, renders the wrong state, loses its draft, duplicates a write or fails to refresh from the Worker.
- **Backend:** a correct authorized app request reaches staging but the Worker/SaaS violates the reviewed route, role, tenant, persistence, validation, idempotency, audit or response contract.
- **Test/environment:** wrong target/package/seed/role, staging outage, missing test fixture or trace, or no safe way to trigger a recovery condition.

Determine the failing boundary before assigning ownership. If evidence is insufficient, classify UNKNOWN and gather a redacted trace rather than guessing.

## Reporting backend-owned issues

For a backend-owned issue, copy the [backend handoff fields](TEST_CASE_TEMPLATE.md#backend-owned-issue-handoff) into a sanitized report: app/package/version/digest, M15 commit and staging sequence; synthetic fixture namespace and pseudonymous IDs; role/capabilities; numbered UI reproduction; expected versus actual; method/path/query; status and redacted response; request/correlation ID; idempotency and row-version observations; post-refresh state; evidence references. Remove credentials, tokens, cookies, patient/staff PII, signed URLs and raw files. Identify the owner as the user's backend team. The M18 worker records the issue for lead review and does not modify backend code or data.

## Acceptance criteria

All documented list/read routes and the create, schedule, and status workflows are observed against staging; successful writes reconcile to one canonical record; validation, capability/session, refresh, and applicable recovery states behave as specified. Role/tenant checks require authorized staging identities; if unavailable they remain explicitly blocked, not passed.

A case is PASS only when its real expected app workflow and API behavior were exercised and evidence is attached. An unavailable role/account, unavailable failure fixture or unexecuted workflow remains BLOCKED or NOT RUN. App acceptance is tied to the exact staging package digest and desktop commit; later package updates require retesting affected cases.
