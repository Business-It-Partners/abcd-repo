## 2026-10-20 — shared native-to-mirror preview handoff

- **Reproduced before fixing:** in a private runtime, I changed the live isolated app page to a bright synthetic state, moved the pointer onto its bottom edge, and read the rendered mirror pixel. The test failed because the mirror still showed the previous capture. This matches the user's pointer-dependent screenshots.
- **Root cause:** the shell synchronously calls `runtime.hideAll()` before changing the front window or showing dock-edge UI, preventing native child views from painting above new shell content. The later runtime sync therefore saw the app view as already hidden and skipped the refresh it previously started only when `getVisible()` was still true. Mirror state could be old or absent. Module callbacks also acknowledged before the updated page had painted, so a selected Finance/Lab module could be replaced by the previous module's mirror during the next hide.
- **Correction:** the shared manager now invalidates the cached bitmap and starts a fresh native-resolution capture whenever a visible app surface is hidden, while still hiding the child synchronously.
