# M19.1 Plan — Dock Click Reliability

**Status:** VERIFIED — 2026-10-26
**Priority:** P1
**Owner:** M19 lead in the existing app-store-infrastructure-audit worktree.

## Objective

Prevent an in-flight launch/discovery request for one installed app from silently discarding a user's dock click on another app.

## Required behavior

- Preserve app identity and one managed window per installed app.
- Allow another app's click to be handled while discovery is in progress, or give clear pending/disabled feedback until it can be handled.
- Repeated clicks for an already-open app activate or restore its existing window.
- Respect the existing two-open-window limit and close-or-cancel dialog.
- Report missing, incompatible, or unverifiable packages through the existing user-facing error path.

## Verification

Use a private UI fixture with a controlled delayed discovery response. Click app A, then app B before A's discovery completes. Verify the click is not silently lost, each permitted app opens at most once, repeated clicks activate the existing window, and a third app still follows the two-window prompt.

Retain the source revision and private test report. Run the focused unit/build checks required for the source change.

## Exit criteria

The concurrent-launch case has a regression test, clear user feedback, and passes on current source without relaxing package verification or the two-window cap.

**Result:** A per-app launch lock replaces the single global lock. The private delayed-discovery regression retains the second app click, prevents duplicate windows on repeat activation, and still shows the two-app capacity prompt for a third app. See [M19 verification evidence](VERIFICATION_EVIDENCE.md#m191-dock-click-reliability).
