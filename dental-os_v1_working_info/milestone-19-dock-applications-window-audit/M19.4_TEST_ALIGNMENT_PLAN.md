# M19.4 Plan — Test Alignment and Launch Feedback

**Status:** VERIFIED — 2026-10-26
**Priority:** P1 for stale workflow coverage; P2 for launch-animation timing.
**Owner:** M19 lead in the existing app-store-infrastructure-audit worktree.

## Objective

Make the dock/window UI suite represent the actual V1 contract and verify launch readiness without depending on a fragile exact timing boundary.

## Required work

- Update or replace stale dock and overview UI tests that expect more than two open app windows.
- Cover the supported two-app flow: open, activate/switch, minimize/restore, close/reopen, and explicit third-app handling.
- Keep the launch-feedback assertions focused on app readiness, minimum foreground hold, and completed handoff. Avoid making readiness depend on a particular animation frame or scheduler timing.
- Preserve reduced-motion behavior. Verify the visual fade only as presentation; it must not determine runtime readiness or window lifecycle.
- Keep Genie minimize/restore visual-only and verify failures/reduced motion settle the same window phases.

## Verification

Run the focused private UI suites and relevant unit tests on the changed source. Retain test output/report files with the source revision. Documentation-only references must not be presented as runtime evidence.

## Exit criteria

The maintained tests match the two-window V1 contract and reliably detect a stalled launch handoff without treating animation timing as app health.

**Result:** Dock, overview, Finance, and usability coverage now follows current app-window behavior and the two-app cap. The launch-feedback test accepts scheduler variation while checking readiness, the minimum foreground hold, and completed handoff; its private UI run passed.
