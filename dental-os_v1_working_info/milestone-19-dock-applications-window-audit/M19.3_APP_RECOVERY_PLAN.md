# M19.3 Plan — App Failure and Recovery

**Status:** VERIFIED — 2026-10-26
**Priority:** P1
**Owner:** M19 lead in the existing app-store-infrastructure-audit worktree.

## Objective

Prove that one failed or unresponsive app can be recovered without making the Dental OS shell or another open app unusable.

## Required scenarios

- Cause app A to fail to start or stop responding while app B is open.
- Verify the shell dock and app B remain interactive and correctly focused.
- Verify app A shows its failure state and a clear restart action.
- Restart app A and verify it can return to a usable state without restarting the shell.
- Close and reopen app A after recovery; verify no stale window/runtime state blocks it.
- Verify dirty-work and pending-unsafe-write protections still prevent an unsafe close or restart.

## Verification

Use a private runtime fixture with deterministic failure/unresponsive injection. Retain runtime state observations, UI assertions, exact source revision, and the test report. Do not infer crash isolation from source inspection alone.

## Exit criteria

The failed app can be restarted independently; the shell and second app remain usable; close/restart safeguards behave as designed.

**Result:** Private runtime fixtures verified independent renderer-crash recovery, restart and reopen, package-integrity failure/retry, and protection against restarting during an unresolved server-write outcome. The shell and the other app remained usable. See [M19 verification evidence](VERIFICATION_EVIDENCE.md#m193-app-failure-and-recovery).
