# M19.2 Plan — Window Controls and V1 Flow

**Status:** VERIFIED — 2026-10-26
**Priority:** P1
**Owner:** M19 lead in the existing app-store-infrastructure-audit worktree.

## Objective

Verify the clinic-facing app and window workflow against current source, including the existing two-app limit.

## Required scenarios

1. Click a dock app and verify its correct managed window opens.
2. Click the same app again and verify the existing window activates without duplication.
3. Open a second app and switch between both apps.
4. Minimize and restore each app; verify its lifecycle and saved bounds settle correctly.
5. Maximize and restore each app.
6. Close and reopen an app; verify it opens without stale window state.
7. Attempt a third app; verify the user can cancel or choose an app to close, with no automatic close.

## Verification

Run the focused UI flow with the repository's private test runner. Exercise both the ordinary Genie path and reduced-motion lifecycle path as supported by the harness. Treat Genie strictly as a visual effect: do not add compositor features or change the V1 window policy to make the test pass.

Retain an exact-source report with each scenario's result.

## Exit criteria

Every listed scenario passes on current source and repeated dock activation does not create a duplicate managed window.

**Result:** The focused dock, Finance, overview, and app-limit private UI checks passed, including both windows' minimize/restore and maximize/restore, close/reopen, app switching, and both capacity-dialog choices.
