## Declared bounds to preserve

Measure the existing contract as implemented; this proposal does not change any limit.

- Broker input envelope: 16 KiB; JSON request body: 12,000 characters; streamed response: 256 KiB; blob read: 8 MiB.
- Broker concurrency: four pending calls per app and eight total; request deadline: eight seconds; appointment list: 200 entries.
- `dentalpkg/1`: outer wire 16 MiB; decoded payload 12 MiB; expanded assets 8 MiB; one asset 2 MiB; 128 files; path 160 ASCII characters and at most eight components.
- M14 currently records a 10 MiB Worker upload limit and an 8 MiB broker blob-read limit. There is no host-mediated upload adapter today. The difference is a contract gap, not an implicit 10 MiB app capability.

For a bound, test one below, exactly at, and one above the stated limit where the contract uses an integer byte/character count. Keep other constraints below their bounds where possible. If a nested package encoding causes an outer limit to mask an inner limit, report that check as structurally unobservable through a valid full-package path; do not claim it passed or change a limit to expose it.
