## App scope

Build from scratch the reception-focused Patient Payments module: patient balance lookup, outstanding/received summaries, partial collection, receipt/ledger confirmation, and source-defined correction behavior. Use the maintained `desktop/fewa_demo/dental-saas` module as the UI/API reference; pin its source revision, then implement in the current Dental OS app structure with the shared UI package and SDK. Build the app UI from the maintained Dental SaaS reference; do not copy SaaS server or transport code.

## SDK and acceptance focus

- Verify the current SaaS API, role policy, and receipt semantics before wiring. Use only the Dental OS SDK; the Worker remains authoritative.
- Enforce the approved receptionist access policy. Test denial for unapproved roles and a separate synthetic tenant.
- Verify partial and full collection, stable operation IDs, duplicate/lost-response reconciliation, conflict/error recovery, and balance/receipt refresh.
- Verify auditability, form validation/dirty state, keyboard/focus, and Store install/update with synthetic financial data.

Keep this package distinct from Finance's Patient payments module because the shipped package identities and role policies differ. Do not infer admin/doctor access from Finance permissions.
