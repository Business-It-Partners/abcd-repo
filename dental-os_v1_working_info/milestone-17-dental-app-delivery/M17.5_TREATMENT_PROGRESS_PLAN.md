## App scope

The app implements the SaaS Treatment Progress worklist with the Dental OS shared UI and SDK. The API returns the server-calculated projection for active patients with open cases and non-cancelled plans that contain at least one pending stage. Each row includes the completed/total stage count, assigned doctors, outstanding balance, and next pending return date. The table shows patient, record ID, treatment plan, completed/total progress, balance, and next return; assigned doctors are not a table column. Doctor search/filter remain available. Progress is compact text without a bar or a remaining-count label. Long treatment plan labels wrap and are limited to two lines. The table has no fixed minimum width so the full row fits without horizontal scrolling. The app also supports patient/record/plan search, sortable pagination, and refresh.

The renderer calls only `GET /v1/treatment-progress` through `ClinicClient`; it has no direct HTTP, credentials, or local authoritative data store. The host requires the `treatment_progress.access` clinic capability before dispatching the route. The SaaS service remains authoritative for tenant scoping and business data. Patient-detail navigation is omitted because the OS has no approved cross-app navigation contract.
