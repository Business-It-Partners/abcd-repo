## Business rules and permissions

- All reads and writes require `finance.manage` (admin).
- Use only the source categories rent, utilities, marketing, maintenance, equipment, taxes/fees, and other, and the source payment methods cash, eSewa, Khalti, card, bank transfer, and cheque.
- The form accepts a valid date through today (matching the SaaS date picker); amount must be positive NPR with at most two decimal places and no more than the Worker maximum. The Worker requires an active default clinic branch.
- A correction requires a reason and creates a replacement record while preserving the prior record/audit link. Void requires a reason and affects only a currently recorded entry. A stale/already changed row returns a conflict; refresh before another decision.
- Every write needs an idempotency key. Worker remains responsible for exact monetary validation, branch selection, tenant and role checks, record status, audit, and cash-flow projection.
- The Worker list returns only currently recorded rows. The void endpoint returns the voided record to the caller, while the Worker retains its void reason/timestamp and audit record; corrections create a replacement and audit link. The directory follows SaaS and lists active rows only.

## API requirements

- `GET /v1/clinic/operating-expenses` returns `{ operatingExpenses: ClinicOperatingExpense[] }`.
- `POST /v1/clinic/operating-expenses` records an expense.
- `POST /v1/clinic/operating-expenses/:id/correct` with replacement and reason.
- `POST /v1/clinic/operating-expenses/:id/void` with reason.
- Existing Finance-family SDK rules already allow these methods and require `finance.manage`. The list API accepts no cursor or date filter and returns the whole list.

## Shared platform gaps and verification

- The shared SDK does not provide host-mediated lookup/recovery for an unknown write after the webview or session is replaced. This UI retains and retries the same command only while the Finance app instance remains mounted.
- `ClinicClient.send` normalizes ordinary Worker 4xx responses to a generic `VALIDATION` error and does not expose the Worker error body. The UI therefore cannot distinguish detailed validation, a missing/stale record, or a missing active default branch; it shows a generic refresh-and-review message without bypassing the SDK.
- Finance remains globally excluded for Reception by the M15 `clinic.app.finance` host policy. This child does not change or bypass that gate; General expenses requires `finance.manage`. Reception access remains deferred as requested.
- The Worker list is unpaginated, has no date filter, and returns current recorded rows only. Month filtering is client-side and the full response is bounded by the SDK's 256 KiB JSON cap.
- The existing Dental OS Finance routes already cover the expense methods and require `finance.manage`; no new shared route rule was needed.
- No tests, builds, type checks, verification, synthetic acceptance, GitHub Actions, signing, bundling, publication, or release steps were run. All completion criteria above remain unchecked.
