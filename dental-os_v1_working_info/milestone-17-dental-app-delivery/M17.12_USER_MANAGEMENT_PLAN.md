# M17.12 User Management

**Status:** STAGING PACKAGE PUBLISHED. User Management 1.0.0 was published at sequence 102. App typecheck/build, OS build, documentation validation, and the 38-check signed public readback passed. Authenticated Store installation and live account-workflow acceptance remain open.

## Scope

Ship the existing Dental SaaS User Management workflow as a normal first-party Dental OS app. It lists clinic accounts; creates Doctor and Reception logins; edits name/role; enables or disables accounts; and changes passwords for linked identities. Admin rows are protected, and an administrator cannot disable their own account.

The app is `company.dental.user-management.m17` version `1.0.0`, with one module (`user-management`). Only an authenticated Admin profile with `clinic_users.manage` can see/install/uninstall or open it. The package and host both declare the Admin-only boundary; the SaaS Worker continues to authorize every account operation.

## Platform and service boundary

The host adds SDK 1.7 family `clinic.app.user-management` and permits only these existing SaaS routes:

| Method | Path | Worker capability |
| --- | --- | --- |
| GET, POST | `/v1/clinic/users` | `clinic_users.manage` |
| PATCH | `/v1/clinic/users/{id}` | `clinic_users.manage` |
| POST | `/v1/clinic/users/{id}/password` | `clinic_users.manage` |

No Worker route, database schema, secret, or deployment change is needed. The app uses `ClinicClient`; the OS holds credentials. Accounts, role decisions, password handling, Firebase identities, tenant checks, and audit/idempotency records stay in Dental SaaS. User account and password values are not persisted to the device.
