# M17.2 Plan — Patient Record

**Status:** PLANNED. App source has not yet been imported into M17.
**Package:** company.dental.patient-record

## App scope

Bring over and complete patient search/list, registration/intake, patient detail and longitudinal clinical records, corrections, and the source-defined patient-record workflows. Preserve the SaaS behavior and present truthful loading, empty, error, conflict, and recovery states.

## SDK and acceptance focus

- Derive every method, route, query, role, and payload limit from current Dental SaaS source and the supported Dental OS SDK contract. Use only the SDK broker for business APIs.
- Verify patient/clinic scope, permitted clinical roles, denial cases, audit/refresh behavior, stable write keys, unknown-outcome reconciliation, and stale-record conflicts using synthetic staging data.
- Integrate X-ray selection, upload, readback, and display through the existing M15 media SDK and host path. Do not implement app-owned network transfer, signed-URL handling, or a parallel media API.
- Verify that the app can only see the current authorized clinic's permitted records/files. Do not add file withdrawal, retention, or deletion behavior; SaaS owns that lifecycle.
- Verify multi-step intake/correction drafts, dirty-form decisions, bounded payloads, keyboard/focus, and managed-window behavior.

M17.2 may implement against the current M15 contract while M15 closeout continues. Mark media proof provisional until the M15 media exit is clean and repeat the affected integration cases on the final M15 source before G14 closure.
