## Scope, page, and workflow

Internal module `product-list` at `finance/products`. Display the product catalogue with text search, category filter, active-only filter, product details drawer, new/edit form, and active-status toggle. Products are catalogue entries used by Purchases; this scope does not add quantity-on-hand, pricing, or inventory valuation that the pinned contract does not provide.

## Business rules and permissions

- All product operations require `finance.manage` (admin).
- Keep Worker categories consumable, instrument, PPE, lab material, office, and other; units box, packet, piece, set, bottle, tube, ml, and gram.
- Product name is required; note is optional; active state is explicit. Updates require `expectedRowVersion`. The Worker returns a conflict for stale versions; reload rather than overwriting a newer product.
- Every create/update uses an idempotency key. Do not locally invent product financial values or stock balances.

## API requirements

- `GET /v1/clinic/products` returns the product list.
- `POST /v1/clinic/products` creates a product.
- `PATCH /v1/clinic/products/:id` changes product fields with `expectedRowVersion`.
- The pinned SaaS `ProductDrawer` also reads `GET /v1/clinic/purchases` and matches purchase lines by permanent `productId` to show recorded purchase history, quantity, and line-value summaries. Dental OS uses this only inside the product detail page; it does not implement the Purchases sub-app here.
- Every read and write uses `ClinicClient`; create/update use an immutable `ClinicCommand` and retries retain the original idempotency key. Updates carry `expectedRowVersion` and a stale response triggers a reload.
- Existing Finance family SDK route rules cover products and purchases. Both lists are unpaginated and each response is subject to the SDK 256 KiB ceiling.

## Dependencies and important states

Requires the Finance shell, shared search/filter/table/modal/drawer components, and Finance SDK route. This child precedes Purchases because that form consumes product catalogue data. Show initial and refresh loading, API error, empty catalogue, no search/category match, form validation/save errors, toggle pending state, stale-version conflict, and safe rollback or reload after a failed optimistic status update.
