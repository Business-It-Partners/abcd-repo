## Source UI

The earlier Dental OS-specific directory, intake, patient, clinical, operations, media and custom stylesheet files were removed. The app directly renders the pinned SaaS `PatientRecordView`, `CaseEntryView`, `PatientDrawer` and production detail tabs. The global and feature stylesheets, shared workspace primitives and date controls are vendored from the same commit. The app root reproduces the source workspace wrapper classes so the production spacing, page sheets, colors, controls and responsive rules apply as authored.

The final full-tree comparison found 117 of 128 vendored files byte-identical to the pinned commit. Seven files contain Dental OS SDK adapters; five local UI paths implement the Files-inspired sidebar and outer content canvas, with `PatientDrawer.tsx` shared between the groups. The central patient views and business workflows remain the pinned source. `apps/dental-apps/company.dental.patient-record.m17/SOURCE_IMPORT.json` lists each adaptation and the upstream Git blob IDs.

## App integration

- `src/main.tsx` — host SDK/session initialization, source-equivalent workspace shell, dirty/modal reporting and stable original-key write reconciliation.
- `src/saasDirectory.tsx` — connect the source directory to paged, clinic-scoped `ClinicClient` search.
- `src/saasPatientIntake.tsx` — connect the unchanged SaaS `CaseEntryView` to patient-intake context, clinic references and the existing create-intake command.
- `src/saasPatientDetail.tsx` — map Worker records to source view models and connect existing routes/capabilities to the production PatientDrawer and tabs.
- `src/saasMediaContext.tsx` and `src/api.ts` — connect Patient Record media and JSON operations to Dental OS SDKs; no direct renderer networking or credential reads.

The source UI remains the same while Dental OS owns signing, grants, identity, permissions, network mediation and runtime lifecycle. The app does not create a local business database or an offline write queue.
